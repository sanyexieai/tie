# MCP 页面保护

普通页面和加密页面保留相同页面 ID、分类、标题与标签。加密页面的正文、历史、讨论和页面图片随工作区保存与同步。标题和标签仍为明文元数据。

## 每次调用授权

本地 stdio 与纯 HTTP MCP 使用相同工具和参数。需要解密内容时，传入本次调用的 `password`；它只在该调用的进程内存中使用，不保存到页面、历史、日志或共享解锁缓存，也不返回给调用方。HTTP MCP 会在服务器内存中解密，因此应通过可信的 HTTPS 地址使用。MCP 不继承桌面客户端的会话解锁或系统凭据库。

一次成功读取不会授权后续请求，也不会授权其他 MCP token。后续调用省略 `password` 就回到锁定视图，无需管理持久解锁会话。MCP 客户端自身是否记录工具参数由该客户端决定，不应将密码写入普通知识页面或持久 Agent 记忆。

- `tie_get`：省略密码返回密文及 `locked: true`；提供正确密码返回正文及 `locked: false`。
- `tie_search`：先按 `root`、`exclude` 和标签裁剪分类，再尝试用本次密码解锁候选正文。不同密码的页面保持锁定，仍可检索元数据。
- `tie_related`：提供密码后从本次解密视图中提取出链和入链，不修改原始文件。
- `tie_write`：新建时传 `encrypted: true` 和密码；加密父页的新子页默认继承加密。修改加密正文时传密码，存储前重新加密。原始密文导入和元数据修改仍沿用已有写权限。
- `tie_revision_get`、`tie_diff`：提供密码后读取或比较历史正文；省略密码保留密文或锁定比较结果。
- `tie_restore`：恢复保留原有历史和版本检查。携带密码时验证当前页和目标版本，实际保存仍为密文。
- `tie_signal_list`、`tie_signal_add`、`tie_signal_resolve`：携带密码即可读取、添加意见、回复及处理说明；写入前加密。本地和 HTTP 使用同一讨论格式。
- `tie_history`、`tie_tree`、`tie_changes` 的元数据查询沿用原接口。

## 双向转换

`tie_page_protection` 的 `action: "status"` 返回保护状态；`action: "convert"` 同时转换正文、全部历史、讨论与页面附件，保持页面身份及分类。转换必须提供密码；`encrypted: true` 表示转成加密页，`false` 表示转成普通页。建议传入 `expectedUpdatedAt`，已有修改则拒绝覆盖。

已有页面不能通过 `tie_write` 直接改变保护模式，避免只加密当前正文却留下旧明文历史。转换失败时保留原页面；处理记录不包含密码或敏感正文。

页面保护的内部 bundle 存储接口只用于客户端转换，不出现在公开 MCP 工具列表中；HTTP MCP 也不能调用这些内部接口绕过密码。

## 跨设备同步

本地 MCP 写入或转换后仍尽力触发一次同步，实际结果看 `sync.state`。当前页面和元数据可自动同步，额外设备独有的历史无法在没有解密授权时自动转换。

若两侧保护模式不同，同步返回带 `[PROTECTION_REQUIRED]` 的冲突，保留两侧正文、历史、讨论及附件，等待用户解锁并显式转换对应工作区；不会用单页上传覆盖对端历史，也不会把转换未完成报告为同步成功。
