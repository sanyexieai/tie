# 工作区加密 Markdown

加密页面的逻辑正文仍是 Markdown；工作区中的 `pages/<标题>.md` 保存下述密文封套。它沿用普通页面的 id、父级、排序、标题、标签与同步流程，不把解密正文交给普通页面存储。`.tie/history`、离线队列、同步端及打包导出只接收密文。

标题和标签等页面元数据没有加密，仍用于目录和元数据搜索。敏感信息应写在加密正文中。解锁后的正文只存在本次应用会话的授权视图中；编辑器、搜索、大纲与关系读取这份视图，持久页面对象始终保留密文。切换页面不撤销会话内的授权；主动锁定该页、换账号或退出应用会撤回对应正文及搜索结果。工作区密码导入为不可导出的 Web Crypto `CryptoKey`，仅在本次应用会话内缓存；密码和密钥不随工作区同步。其他设备需要输入相同密码解锁。忘记密码将无法从密文恢复正文。

## 普通页面体验

加密是页面的访问保护，不使用另一套编辑器。解锁后与普通页面共用 `DocumentEditor`、标题和标签、查找替换、源码、收藏、关系面板及历史界面，只在顶栏增加锁定入口。正文保存前加密，历史预览和刷新则在授权后解密；查询未解锁的正文时，可在普通搜索界面额外解锁当前工作区范围。

私密图片内嵌在 Markdown 中，再随正文整体加密，不另存明文图片附件；子页和新建的链接页面继承加密。智能标签在本地提取，不向外部 AI 服务发送加密页面的正文。

讨论仍使用普通页面的引用、回复和处理流程。加密页面的引用与意见正文合并加密在记录的 `body` 中，`quote` 留空；处理说明和手动版本正文也分别加密。记录的作者、时间、状态等元数据保持可见。锁定后撤回讨论明文及未提交的讨论草稿；跨工作区迁移复制原始密文，不使用解密后的界面数据。

## 密文格式 v1

```text
-----BEGIN TIE ENCRYPTED MARKDOWN-----
{"version":1,"algorithm":"AES-256-GCM","kdf":"PBKDF2-SHA256","iterations":600000,"salt":"<Base64>","iv":"<Base64>","ciphertext":"<Base64>"}
-----END TIE ENCRYPTED MARKDOWN-----
```

- 首行是加密类型标记。即使内容损坏，也必须继续按加密页面打开，不能退回普通编辑器展示或保存。
- `salt` 是每次保存生成的 16 字节随机盐；密码使用 UTF-8 字节，经 PBKDF2-HMAC-SHA-256、600,000 次迭代，派生不可导出的 256 位 AES 密钥。
- `iv` 是每次保存重新生成的 12 字节随机值。`ciphertext` 是 AES-GCM 密文与 128 位认证标签的拼接。
- 认证附加数据是 UTF-8 `tie:encrypted-markdown:v1`。它绑定格式用途与版本，不绑定工作区 id，因此原样复制、迁移和跨设备同步的密文仍可用原密码打开。
- v1 只接受上述算法及固定迭代数。盐、iv 和密文严格校验后才运行密钥派生，不能通过文件内容指定任意大的计算量。认证失败不会返回部分正文。
- 文件通常使用 LF，也接受 CRLF 和开头 UTF-8 BOM；正文解密后保留加密前的 Markdown 字节内容（UTF-8）。

这里使用平台内置 [W3C Web Crypto AES-GCM / PBKDF2](https://www.w3.org/TR/webcrypto/)；600,000 次 PBKDF2-HMAC-SHA-256 采用 [OWASP 的 PBKDF2 工作因子基线](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#pbkdf2)。加密模式选择符合 [OWASP Cryptographic Storage](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html#cipher-modes) 对认证加密的建议。

## 与服务器凭据库的关系

工作区加密文档和服务器的固定 HTTP 操作凭据是两种数据。旧凭据库的 token/password 仍按原有方式维护和授权，不会自动转成 Markdown 或把整篇文档用作 HTTP 认证值。MCP 不会获得客户端会话中的授权视图。

本地 stdio 与纯 HTTP MCP 都支持每次调用单独提供 `password`：读取、正文搜索、编辑、新建、关系、历史预览与比较恢复、讨论和回复沿用普通工具，在调用内解密或加密，密码不持久保存。省略密码时仍返回锁定视图和元数据搜索；后续请求或其他 token 不会继承一次成功解锁。HTTP 模式会在服务器内存中使用本次密码，因此需要信任该服务器并使用 HTTPS；客户端自身是否保留工具参数由该客户端决定。详见 [MCP 页面保护](./mcp-page-protection.md)。

## 普通页面与加密页面互相转换

转换保留页面 ID、分类、元数据、历史和讨论记录，同时转换当前正文、历史正文、讨论、处理说明与页面附件。引用的安全图片内嵌后加密，未引用附件作为加密数据保留；不能用普通保存直接改变已有页面的保护模式。转换前检查整页、历史、讨论和附件快照，期间任何内容变化都会拒绝覆盖。

MCP 使用 `tie_page_protection(action="convert", encrypted=true|false, password=...)` 执行同样的转换；客户端在本机完成密码或已授权密钥的加解密，后台 bundle 接口不接收客户端密码。转换为普通页意味着正文、历史与讨论恢复普通明文保存。

绑定服务器时，各存储源的历史可能不同，显式转换会分别处理已有副本。其他设备未提供解密授权时，同步不会自动把不同保护模式的页面相互覆盖：返回带 `[PROTECTION_REQUIRED]` 的冲突，保留两侧正文、历史、讨论及附件，要求在对应设备解锁并显式转换后继续，不会把转换未完成报告为已同步。

## 在此设备记住解锁

Windows、macOS 和 Linux 桌面客户端可选择「在此设备记住」。仅在用户明确选择后，解锁密码才通过已有 [keyring 系统凭据库](https://docs.rs/keyring/3.6.3/keyring/) 保存到当前设备：Windows Credential Store、macOS Keychain 或 Linux Secret Service；不会写入工作区、浏览器存储或普通配置文件，也不会随知识库同步。条目使用独立服务名，账号、工作区和页面的组合经 SHA-256 处理后作为标识，不在系统库条目名中暴露原始地址和路径。

锁定该页会清除该页的授权正文，退出会清除本次会话的全部授权正文，但保留用户选择记住的本机凭据；「忘记本机解锁」从系统库中删除它。系统库不可用时继续使用密码解锁，不降级到普通文件保存。网页、Android 和 iOS 不提供此持久记住功能。

这个选项依赖当前系统账户和凭据库的保护，并不是证书导入，也不保证每次读取都会弹出系统身份验证。其他设备仍需密码，或在那台设备上单独选择记住。

Linux 的 Secret Service 连接开启 keyring 的 `crypto-rust` 特性，对密码经过本机 D-Bus 的传输也使用库提供的加密会话。
