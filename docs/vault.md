# 服务器凭据库

凭据库独立加密保存密码、令牌等敏感值，让 Agent 使用已授权的密钥执行固定 HTTP 操作，密钥原文不进入 MCP 响应。客户端左侧称为「操作凭据」；这些条目不属于普通 Markdown 页面，不进入页面历史、知识库导出或 `.tiez`。

「新建页面 → 加密页面」创建的是[工作区加密 Markdown 文档](./encrypted-markdown.md)：解锁后使用普通页面的编辑器，支持本地编辑、加密历史和密文同步。它与这里的固定操作凭据分开，旧 token 不会自动转换成文档。不要通过普通 `tie_write` 写入敏感明文；工作区只能接收加密封套。

## 保存和维护凭据

在客户端点击左侧「操作凭据」旁的 `+`。只填名称和密钥即可保存；服务、环境、标签和说明可在「分类与说明」中补充。已保存的凭据显示在左侧，搜索只查元数据；密钥只填入专用密钥区。

凭据需要登录服务器后使用，默认选择当前服务器的默认工作区；可在左侧切换工作区。名称、密钥、查看与复制、修改和删除都在凭据页面内完成，不再要求跳到网页。值仅在本页明确点击后读取，切换页面或账号、退出、关闭页面后清空原文和输入；草稿不存入浏览器缓存。服务器 `/me/#vault` 仍可管理同一份凭据。

单纯保存凭据不要求填写 HTTP 地址。需要 Agent 调用服务时，展开「Agent 使用与授权」，开启「配置固定 HTTP 操作」，填写固定 HTTPS 地址、方法与认证方式：Bearer、自定义请求头，或 Basic 用户名与密码；可设置固定请求内容。Agent 使用时不能更改目标、方法、认证方式或请求内容，不能执行任意命令或 shell。

列表只显示说明和操作摘要。编辑或打开「详情与授权」时，才读取完整的固定操作配置；不会自动读取密钥。查看、复制密钥需要所有者明确点击对应按钮，退出或离开凭据库会清除页面中的原文。编辑时密钥留空表示保留原值。修改凭据会增加版本号，使旧版本授权失效，使用前需要重新授权。

默认只将执行结果的 HTTP 状态返回 Agent。所有者可在「允许返回的字段」中逐行选择 JSON 字段路径，如 `status`、`data.id`；仅支持标量，不支持数组、通配符或任意表达式，返回内容仍会脱敏。只对可信目标开放返回字段，脱敏不能保证识别任意编码、拆分或变形后的密钥。不要把认证值放入地址、名称、说明或标签。

## 授权与撤销

凭据的所有者在客户端「Agent 使用与授权」或网页「详情与授权」中检查固定地址、HTTP 方法、请求内容和返回字段，保存配置后再选择调用者：此工作区的 MCP 令牌、当前登录会话，或本人其他活跃登录会话。其他会话显示短 ID 和到期时间，选中后可核对完整 ID；桌面或 HTTP 客户端给出的会话 ID 可能与账号页当前会话不同，应按实际连接的 ID 匹配。列表不包含会话令牌或 hash。授权会绑定具体凭据版本及调用者身份，不能由其他账号、其他令牌或其他登录会话复用。

- 「仅一次」在发出外部请求前消耗，最多允许使用一次，网络失败也不会返还或自动重试；需要再次执行时由所有者重新授权。「有效期内持续」允许在期限内多次使用，但也不会替用户自动重试。
- 界面提供 1 小时、24 小时和 7 天有效期，默认为一次、1 小时。
- 在「操作授权」中撤销授权；删除凭据后，其固定操作也不能继续使用。
- 「使用记录」按工作区和凭据查看执行中、成功、失败与拒绝记录，以及 HTTP 状态或失败原因。新记录还显示固定方法、origin、凭据版本和授权 ID，不显示目标路径、请求内容或密钥原文；较早的拒绝记录可能没有这些字段。

没有有效授权时，Agent 应提示所有者到 `/me/` 授权，不能自行创建授权或要求用户把原文粘贴进对话。一次授权不是对执行成功的承诺；失败或拒绝的具体结果以使用记录为准。

## MCP 使用

这组能力只在服务器 HTTP MCP 上提供，沿用调用者原有的登录会话或 MCP 令牌身份及工作区范围。MCP 令牌用于证明调用者身份，凭据库中的密钥用于向固定目标认证，两者不能混用。

1. `tie_secret_search({query?, service?, environment?, limit?})` 只检索凭据说明等元数据，不检索或返回密钥原文。
2. `tie_secret_use({secretRef, grantId?})` 使用该调用者已有的有效授权，在服务器执行固定 HTTP 操作。`secretRef` 使用搜索结果中的引用，例如 `secret://sec_example`；可指定已有授权 ID。它不会返回密钥，也不接受新的 URL、命令或请求内容。
3. `tie_secret_usage({secretRef?, limit?})` 查看当前调用者可访问的使用记录。

搜索结果的 `action: null` 表示仅保存，尚未配置可执行操作。此类凭据的授权或执行返回 `ACTION_REQUIRED`，不会解密值或发出外部请求；所有者在凭据页面配置并保存固定操作后再授权。移除固定操作时保留密钥，旧授权失效。

例如先按服务和环境搜索，再使用匹配的引用；缺少授权时停止执行，将错误中 `principal` 的类型和 ID 告知所有者，请其到账号页选择对应调用者授权。不要把凭据值写回页面或日志，也不要为了使用凭据绕过 HTTP 连接与授权要求。

## 服务器配置与备份

凭据采用服务器托管加密，不是端到端加密。服务器需要主密钥和凭据数据来解密并执行已授权操作；能够取得两者的服务端管理者也能够解密。

凭据、授权和使用记录保存在服务数据目录的 `vault.json`，不在工作区目录内。加密主密钥独立于工作区，默认文件为服务数据目录下的 `.private/vault.key`，可通过 `TIE_VAULT_KEY_FILE` 指定外置私有文件。外置文件需预先提供 32 字节随机密钥，也支持其十六进制或 Base64 表示；权限应只允许服务用户读取（Linux 为 `0600`），与工作区、公开静态文件和知识库导出分开管理。迁移位置时保留同一主密钥。备份凭据数据时也要安全备份主密钥；丢失主密钥将无法解密已有凭据。

固定目标默认限公共 HTTPS 地址。管理员可通过 `TIE_VAULT_ALLOWED_ORIGINS` 配置精确的 HTTPS origin，以允许指定的内网或 loopback 服务；这不会放开其他地址，link-local 和云元数据地址始终禁止。所有者应只为实际需要的固定操作选择适量返回字段。
